# 启明官网怎样管理自己的文章、发布和验证

启明官网本身也是一个由启明管理的项目。这个案例说明：写完源码、跑通构建、推上 GitHub、部署到正式域名，是四种不同的事实。内容也要接受同样的检查。

## 原来乱在哪里

官网要同时承载四种语言、像素风、手机底部导航、安装说明、真实案例、用户反馈和更新日志。若这些需求只留在对话里，下次改版时很难知道哪些已做、哪些只在本地、哪些已经上线。文章曾把多个领域的案例塞进一篇长文，读者需要在 15 节中来回找事实；标题、边框和正文层级也需要稳定规范。

## 启明做了什么

官网改造先作为工作任务记录目标和验收。源码归官网会员，文章是内容产物；一篇 Markdown 不会因文件后缀自动成为会员。构建时生成四语言栏目与独立主题页；没有对应译文的文章只发布简体中文全文，其他语言的栏目卡明示可阅读语言，不伪造译文页面。

发布按可检查的顺序走：本地生成页面并运行测试；按公开发行白名单打包，检查私人目录、项目原名、账户和密钥是否泄露；更新 GitHub 仓库；部署 Cloudflare Pages；最后在正式域名看读者真实路径。每一步的结果和未验证项分别回写项目任务。文章栏目另有固定排版约定，规定标题层级、阅读宽度、边框、代码块和手机视口检查。

## 留下了什么

项目保留官网源码、四语言页面元数据、文章目录与原文、发行脚本、测试、更新记录和下一次发布入口。长文被拆成现在这个系列：总览、本机 AI、Pi Agent 子会员、交付边界、研究与运营、官网发布。旧文章地址继续承载总览，已有链接不会变成空页；每篇从问题、动作、产物和验证边界讲一个明确主题。

更重要的是一条可接续的责任线：内容来自真实项目档案，公开文本经过脱敏；代码与页面由官网会员维护；每次发布任务保存发布证据。一个案例采集或脱敏流程若以后被反复使用，并有独立入口和维护周期，才考虑提升为子会员。

## 验证到哪里

本地测试通过，只证明本地构建与约定检查通过；GitHub 更新，只证明远端源码可取；正式域名加载，还要实际检查栏目到文章的点击路径、CSS、桌面和手机排版。搜索引擎是否收录、AI 是否引用、读者能否理解文章，需要另外观察，不能由一次部署推出。

这个网站也要允许读者指出问题。用户发现文章空洞、项目名称未脱敏或手机样式难读，问题进入官网工作记录，回到案例事实和页面检查修正。启明作为管理工具，不能给自己的发布开后门。
