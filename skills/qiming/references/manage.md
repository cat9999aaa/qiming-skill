# 管理当前工作

1. scope_check 核对项目，读 START.md 与当前记录。
2. search 定位已有归属；有持续工作才建任务。
3. log_event 追加事实；修改其他字段用 plan/apply。
4. 核验用户能观察到的结果，再更新状态、证据和下一步。
5. 短入口以 3–5 项当前工作导航为主，旧记录不在每次启动全文加载；具体路径依清单。


开始实际工作前，核对本实例与当前项目范围，读取短入口、本地约定和当前任务；不以用户是否说“启明”作为条件。任务至少说明目标、范围、可观察的验收条件和下一步。普通一次问答不必新建任务；有跨步骤、跨会话或持续产物时建立或续写工作记录。

先定位本次工作服务的会员或项目。产物按[会员判断](members.md)分别归为附属成果、证据、外部依赖或独立会员；保留复用的独立能力登记身份、用途、入口、责任、父级与来源任务。用户无需另说“入会”。

同一对象只保留一份权威记录；旧 `MEMBER.json` 能映射时原地接入。名称、内容指纹和 Git 工作树不决定会员身份。首次建立记录时分配稳定 ID；已有 ID 不重写。未知状态保留在原字段，通用生命周期保持未知。关系只记录一个方向，`part_of` 不能成环；不可访问的外部引用留作未解析。

结论只依据实际读取或执行的结果。已有资料与最新现场冲突时显示冲突；未运行的检查保持未验证。产生可复用经验时，先找是否已有对应记录，再更新或新增。

工作记录写清目标、范围、逐条验收、进展和下一步。完成状态逐项关联当前对象版本和范围内的实际证据；文件存在不替代执行通过。中断时保留最后已证实的步骤与可执行下一步。状态与会员生命周期分开。更新权威记录走 `plan → apply`，出错后检查操作日志再 `reconcile`。

事故或高压任务可以用 `log_event`（或 `qiming.py log`）向**已有工作记录**追加一条观察、行动、决定或交接。该入口内部仍走同一事务，保留指纹冲突和操作日志；稍后再补验收与总结。动态状态写观察时间，接手时先现场复核，不能把“当时可用”当作现在可用。事件摘要只写事实与必要来源，不放凭据值。

有持续成果的工作收尾前，核对四件事：产物能否从所属会员/项目找到；新独立能力是否登记并关联来源；验证和可复用经验是否有依据；短入口是否仍准确指向当前进度与下一步。只更新真正变化的记录；结果表、测试输出和临时文件不因此各建一名会员。需要执行的验证实际运行，未运行的部分明确保留。长任务中途也更新可接续的进度。

目录跟随真实产物形成：任务需要时保存任务，结论值得复用时保存知识，产生工具时保存脚本/Skill/程序及必要测试。沿用原目录，通过本地映射连接；既不预建空的分类树，也不让长期成果只留在聊天里。改变关键偏好或职责时，在本地启动摘要维护简短结论并 `refresh_context`，详细依据仍在原权威文件。

账户卡只保存用途、关联工作、凭据服务的定位引用与恢复入口。密码、令牌和私钥值只进入专用密码库或系统钥匙串；未有适合的存储接口就记录缺口。归档、退出、合并、删除前先查看调用者和影响清单；删除还要检查派生索引、可控导出与已知备份。影响清单是提案，实际权威文件变更仍须准备内容并走 `plan → apply`。

## 长期记录

知识可设 `review_after`（ISO 日期或带时区时间），search 会给到期结果标 `review_status: due`；不是自动宣布原结论错误。已完成任务可设置 lifecycle: archived，默认搜索不显示，用 include_history: true 查回。保留 ID 与引用路径；如需按月移动目录，先检查引用并做受控迁移，不自动批量搬走用户文件。

完整的快速追加与搜索请求及结果位置见 [入门闭环](quickstart.md#记下来找回来)。


## 收尾时分开核对权威记录与启动摘要

`refresh_context` 只把清单 `startup_context` 指定的源文（默认 `startup.md`）写入受控的宿主指令区块。它不会更新清单 `workspace_entry` 指定的短入口（默认 `START.md`），不读取链接里的任务，也不判断作者摘要是否正确。`binding_status=bound/bound-copy` 只说明发现入口、复制件和生成上下文的相应检查通过。

当进度改变时，按本次实际影响处理：

1. 先更新并读回相关权威任务/会员/证据，保留观察时间、版本和未验范围。
2. 对照这份权威记录核对短入口；若重复了旧进度，只改真正过时的摘要。优先保留权威链接，不在多处复制快速变化的提交号、步骤和设备状态。
3. 若本次改变影响第一步决策、职责或关键偏好，再更新启动摘要源；仅业务详情改变时，不强制把它们复制进启动摘要。
4. 源文变化后调用 `refresh_context`，然后读回相应短入口、生成区块和本次权威记录。刷新成功不等于前两步已完成。

成功响应中的 `context_coverage` 把 `short_entry`、`linked_records` 和 `summary_accuracy` 标成 `not_checked`。这是未检查的范围，不是判定摘要过时或准确；不能把它改记成“全量状态已同步”。并发改动先重新读取原件，通过指纹计划处理冲突，不用刷新覆盖用户文本。
