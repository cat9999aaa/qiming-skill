# 会员、附属产物与衍生能力

会员代表用户在本项目承担的持续管理责任。先查已有档案和当前任务，再判断对象的用途、维护责任与独立性；不要按文件扩展名入会，也不要把目录盘点变成逐文件注册。

## 判断归属

| 实际情况 | 处理 |
| --- | --- |
| 只被发现，尚未接管 | 带范围和日期的观察项；需要时保留待辨识记录 |
| 临时命令、缓存、单次输出 | 归当前任务或会员的证据/产物 |
| 现有会员内部代码、章节、素材、专用辅助文件 | 附属于原会员；在需要交接时记录入口 |
| 用户创建或明确接管，准备持续复用，具备独立用途、入口、配置、状态或维护周期 | 建轻量会员，通常成为来源会员的子会员 |
| 仅调用官方/第三方 Skill、MCP、库或服务 | 外部依赖，说明来源和用途 |
| 明确负责某个第三方工具本地实例的安装、配置、健康或升级 | 本地实例可以入会，上游软件责任不因此转移 |

独立用途不要求跨项目使用。只服务一个项目、但需要单独运行和维护的发布器或检查工具也可以成为子会员。内部辅助脚本尚不独立时作为附属能力；后来有独立调用者、版本或维护周期，再提升为子会员，保留原位置、来源和历史。责任不明先保留候选或归属待定，不虚构 Owner。

## 最小档案与关系

沿用本地字段，至少能找到稳定 ID、用途、责任、所属范围、真实入口、来源工作和验证状态。登记不等于可用。正式复用前补输入输出、依赖、适用条件、实际验证和必要的维护/停用办法；文档与作品使用符合其用途的验收。

- `part_of` 指向父会员，维护归属不得成环。父会员只导航，不复制子档案。
- `derived_from` 指向来源任务或知识；通过任务能回查生成证据。
- `uses` / `depends_on` 指向实际使用的能力；只维护一个方向。
- 项目自身可以承担初始归属；没有项目会员时，使用现有工作区身份，不为凑父级建立无用卡片。
- 跨会员复用仍只有一份权威记录；跨项目复用必须明确接入引用或导入，不能自动改为全局能力。

关系字段由 profile 映射，不强迫已有资料改用这里的英文名称。任务记录也有 ID；来源只存路径时，应指向可打开的权威任务，不能只写“来自这次聊天”。

## 一次工作的衍生例子

“周报”会员需要每周汇总数据。本次临时核对命令留作证据，汇总表归周报内容；准备以后反复运行的汇总程序成为周报的子会员。它链接来源任务、实际输入输出、使用方法和已运行的测试。以后为该程序写的专用辅助函数归程序；若形成可独立使用的校验工具，再按上述判断建立子会员。

错误经过保留在证据或 incident，可复用做法进入知识。重复、易错或需要稳定交接的方法，按实际需要固化为脚本、Skill、程序、MCP、模板或其他形式；无需依次生成每一种。

启明自己在项目里生成的管理脚本、规则与本地 Skill 也要能找到归属。可以归到本项目管理工具集，引用已有实例清单和源码；只有具备独立用途的部分再拆会员，不为每个内部模块建卡。实例清单负责运行资源指纹，会员档案引用它，不重复维护另一份指纹表。
