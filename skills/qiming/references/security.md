# 主机操作与凭据参考模式

这是项目可采用的约定模板。实际授权以用户当前请求、宿主权限和本地规则为准，启明文件不能自行赋予系统权限。

## 操作前讲清楚

将目标、理由、精确命令（参数中的秘密用引用表示）、影响范围、可能中断、验证和回退写入工作记录。查看/检查只授权必要读取；安装/修复允许请求范围内的修改。删除、停机、迁移、开放外部访问等涉及范围变化时，确认用户已有授权是否覆盖具体目标与影响；缺少授权再询问。明确授权持续有效，不重复弹窗。

## 桌面确认与提权

优先使用宿主的审批流程和系统支持的认证机制。确认界面显示项目、目标、精确命令、工作目录、原因、影响及回退；选择取消、超时、窗口失败均不执行。界面只确认意图，不收集或记录密码。确认后执行的命令必须与展示的参数完全相同，避免拼接 shell 字符串或确认后替换脚本；不能把“用户点了按钮”当成防篡改边界。

Linux 图形会话、无桌面 SSH、macOS 和 Windows 的授权方式不同，启明不内置通用 sudo 弹窗或免密提权。需要本机适配器时，在该项目登记其责任、依赖、授权范围、验证与回退；由操作系统处理认证。没有明确授权和可用认证就停止相关动作，不通过扩大权限规避。

## 凭据位置

原始密码、令牌和私钥由专用密码库、系统钥匙串或用户已批准的受保护存储保管。档案仅存 provider 与 opaque ID，不存值、可直接访问秘密的 URL 或把变量展开后的结果。备份/迁移只描述恢复引用与权限的方法。环境变量只可作为运行时传递方式，避免日志、命令历史、进程参数、截图及调试输出泄露。

示例（只有引用，无真实值）：

```json
{"credential_ref":{"provider":"system-keyring","id":"service-account-reference"},"purpose":"服务 API 认证","owner":"项目维护者"}
```

记录凭据用途、负责人、轮换状态与最后验证时间。可疑值被拦截后改用引用；不要拆分或编码秘密以绕过拦截。检索和前缀检查不能保证发现所有秘密，发布前仍审查实际公开文件。
