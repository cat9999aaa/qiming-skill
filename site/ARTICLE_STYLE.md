# 启明文章样式与发布约定

文章页是阅读界面。像素风保留在品牌标识、短标签和少量橙色强调；连续正文保持平静、清楚。新文章复用现有组件，不为单篇文章另写一套版式。

## 固定层级

- 栏目页使用一个 H1；文章卡的标题使用 H2。单篇文章使用一个 H1；正文从 H2 开始，小节用 H3。标题和目录顺序来自文章源文件。
- 单篇文章先显示返回栏目、日期、短标签、标题和摘要，再显示目录与正文。摘要取 `articles/catalog.json`，不能在四种语言索引中暗示不存在的译文。
- 桌面正文宽度上限为 740px，17px 字号、1.88 行高；手机为 16px、1.85 行高。正文使用纯色背景，长文不要叠像素网格。
- H1 用浅色，橙色用于短标签和摘要左边线。H2 用一条细分隔线区分章节，H3 用绿色。不要让每级标题都变成橙色大字。
- 栏目卡片用 2px 中性边框，悬停才变橙；目录用 1px 中性边框加左侧橙线；代码块用中性边框加左侧绿线。避免整篇文章被亮色粗框围住。
- 桌面目录位于正文左侧；手机目录默认折叠，但必须可以用键盘和触屏展开。代码块可以横向滚动，正文不能产生页面级水平滚动。

## 新文章的写法

1. 在 `site/articles/` 增加原文，第一行只写一个 `#` 标题；正文用 `##` 和必要的 `###` 分层。当前小型渲染器支持段落、标题、围栏代码、行内代码和 URL；其他 Markdown 语法需先扩展渲染器再使用。
2. 在 `site/articles/catalog.json` 登记 slug、日期、各语言的索引标题、摘要、语言状态和真实存在的原文。不要为没有全文的语言生成详情页或 `hreflang`。
3. 故事和案例保留事实来源、执行动作、实际验证和未知项。公开前检查项目原名、私人路径、账号、密钥和内部地址。

## 每次发布检查

1. 构建 `site/dist/` 并运行项目测试。CSS 和 JS 链接由内容哈希生成；改样式后地址必须变化，避免旧缓存与新 HTML 混用。
2. 在浏览器检查桌面栏目与详情页：首屏能看见文章入口，H1、摘要、目录、H2、代码块和边框层级清楚。
3. 在 390px 手机视口检查栏目与详情页：底部导航不遮住内容、目录可展开、正文无水平溢出。再检查一篇文章的中段和末尾。
4. 发布后在正式域名复查 CSS URL、实际计算样式、栏目到详情的点击路径，以及文章正文；HTTP 200 本身不算视觉验收。

参考：[MDN 的资源缓存建议](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control#caching_static_assets_with_cache_busting)、[W3C 的文字间距说明](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing)、[W3C 的页面结构与行宽建议](https://www.w3.org/WAI/tutorials/page-structure/styling/)。具体字号、宽度和配色是启明自己的设计取舍。
