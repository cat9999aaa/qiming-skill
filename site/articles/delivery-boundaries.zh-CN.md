# 两个交付现场：先找对主项目，再分清测试与验收

项目名和私人路径已脱敏。这里展示两个不同项目里的同一个问题：如果 Agent 从错误的目录开始，后面再认真执行，也可能得到错误的“完成”。

## 原来乱在哪里

第一个项目是客户交付。合同、两套活动源码、体验环境、服务器、域名和一条旧开发线同时存在。旧目录的名字很熟悉，接手者容易在它里面开新会话，把历史归档当成今天的发版入口。体验版可以打开，又容易被误写成“客户项目完成”。

第二个项目是驾校学习与模拟考试系统。仍在使用的旧考试系统，与新建的局域网学习 VM 承担不同职责；后续还要面对教练和旧 Windows 考台。若把“修新学习页”的任务作用到旧系统，或把本地测试当作所有考台可用，后果都超出原任务。

## 启明做了什么

客户交付项目在正式主目录建立独立启明实例。短入口先说明旧开发线是历史归档，当前源码、合同优先级、服务器与域名档案，以及交付任务从主目录导航。Agent 先读当前任务，再进入相关源码仓库，并核对该仓库是否有自己的项目边界。启明没有删除旧线，也没有为整齐而移动所有源码。

驾校项目的入口把旧考试系统列为生产事实源，未经核实不能修改。新学习 VM、版本、题库、教练授权和现场试点分别记录。一次任务结束时，写入的是当前版本做了什么、如何回退、下一位 Agent 应查看哪份状态与证据。长篇历史留在原位置，新会话先读短入口。

## 留下了什么

客户项目留下主项目入口、当前源码指向、合同与交付任务之间的关系，以及环境和域名等长期对象的维护档案。旧开发线继续保留，但被明确标为历史资料。这样接手的人能解释为什么从主目录开始，而不是凭名字选一个子仓库。

驾校项目留下版本、题数、测试、发布记录和回退线索。短入口指向当前 `STATUS.md`、方案和验收证据。它没有把整套旧生产系统复制成新项目的目录，也没有让用户从几十页历史里猜下一步。

## 验证到哪里

客户项目已有公开体验版、角色页面检查和部分业务流程实测；合同剩余项目、客户原失败案例及真实设备链路仍需各自验收。网页能打开，只能证明当前网页可访问。

驾校项目的本地测试和局域网 API 检查已有记录；真实教练独立操作和一台旧考台上的完整流程仍未由这些检查证明。下一步应按具体环境和具体人继续验收，再更新结论。这个案例说明，启明留下的“未完成”并非拖延，而是避免下一次接手时误用结论。
